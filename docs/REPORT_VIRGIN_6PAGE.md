## 1. Problem framing: what "good" means for Virgin, what we didn't build

Brand **VirginTrains** — 27,817 outbound / 37,444 inbound pool (union 65,346, 2.32% of TWCS 2.8M; Oct–Nov 2017 burst 91%). Good = acknowledge → concrete next step (Delay Repay operator-form routing / amendment buy-new+refund-old flow / live-departures check) → DM redirect with journey + date + booking ref; never invent times, platforms, or prices (£/HH:MM must be grounded in inbound or passages or omitted); station names (euston 4,220 / manchester 1,442 inbound hits) are slot entities, never keywords. Escalate with reason on: safety (overcrowd/evacuation/injury/stranded + base legal lexicon), money (delay_claim / ticket_change_refund / fare_ticketing below 0.70 + £/refund signal), human request / injection, unresolvable (low-conf <0.45 / no-grounding / link-only / non-English / vague+frustration), complaint-review (frustration + sensitive). Output JSON: brand, intent, confidence, draft_reply, passage IDs, decision, reason, draft_path (template|groq), groq_reason. **Not built:** actual refunds/compensation processing, live National Rail / operator backend, multilingual (non-English → other + escalate), post-2017 timetable knowledge, autonomous resolution, Groq live path without key (keyless default; Groq behind schema+gate, fail-closed to template). UI is demo-only (direct agent import); engine first. See `research/datasets/virgin_data_quality.md`, `evaluation/virgin/SAMPLING_NOTE.md`, `src/virgin_intents.py`.

## 4. What is misleading about my headline number? (mandatory)

- Any **~1.000 weak-200** Virgin number is **circular**: weak labels were frozen with pre-fix keyword rules, so simple scores 0.975 and final's train-subset acc 0.969 is equally circular. Never cite weak-200 accuracy. True ceiling is weak-vs-human agreement (Virgin 0.795, κ 0.772 on 200) — and the old "simple beats final on intent" story is DEAD here: balanced weights put final ahead 0.795/0.803 vs 0.790/0.796. Small-n (±0.07 CIs) means that lead is noise-level, not a victory lap.
- Virgin **human-200 is single-annotator AI-assisted** (60 manual-style + 140 rulebook-assisted, 41 flips; no inter-annotator κ yet — 50-item pack ready for annotator 2). n=200 → CIs ≈±0.07 on acc; per-intent F1 on ~14–29/stratum unstable (±~20%). Citing Apple human numbers as Virgin results would be a transfer fallacy — Apple rows above are reference only.
- Groundedness 0.900 ≥4 (mean 4.21; judge-harness heuristic says 1.000/4.32 — two heuristics, same caveat) rewards templates by design, not human factuality. Safety recall 1.000 on **n=3** has CI ~0.4–1.0 (gate NOT claimable); money recall 0.850 on n=20 is the better-powered signal. Keyed LLM-judge v1 κ=0.253 / v2 κ=-0.005 both fail the wκ≥0.60 gate — the "proof" rests on human-200 + escalation slices, not on any judge.
- Latency (virgin index p50 7.1ms) is dev-CPU, not prod; burst-month slice (post-2017-11-15) + thin pre-2017 tail shift results; 9/9 failure-PROBE pass rate flatters (probes are fixed known cases with regression tests — they guard against relapse, not unknown unknowns).
- Trust esc-vs-human κ 0.715 + money slice (0.850) + flips + the two failed judge gates, not a single accuracy. Full double-label + adjudication needed for ship.
