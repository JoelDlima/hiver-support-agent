## 1. Problem framing: what "good" means for Virgin, what we didn't build

Brand **VirginTrains** — 27,817 outbound / 37,444 inbound pool (union 65,346, 2.32% of TWCS 2.8M; Oct–Nov 2017 burst 91%). Good = acknowledge → concrete next step (Delay Repay operator-form routing / amendment buy-new+refund-old flow / live-departures check) → DM redirect with journey + date + booking ref; never invent times, platforms, or prices (£/HH:MM must be grounded in inbound or passages or omitted); station names (euston 4,220 / manchester 1,442 inbound hits) are slot entities, never keywords. Escalate with reason on: safety (overcrowd/evacuation/injury/stranded + base legal lexicon), money (delay_claim / ticket_change_refund / fare_ticketing below 0.70 + £/refund signal), human request / injection, unresolvable (low-conf <0.45 / no-grounding / link-only / non-English / vague+frustration), complaint-review (frustration + sensitive). Output JSON: brand, intent, confidence, draft_reply, passage IDs, decision, reason, draft_path (template|groq), groq_reason. **Not built:** actual refunds/compensation processing, live National Rail / operator backend, multilingual (non-English → other + escalate), post-2017 timetable knowledge, autonomous resolution, Groq live path without key (keyless default; Groq behind schema+gate, fail-closed to template). UI is demo-only (direct agent import); engine first. See `research/datasets/virgin_data_quality.md`, `evaluation/virgin/SAMPLING_NOTE.md`, `src/virgin_intents.py`.

## 4. What is misleading about my headline number? (mandatory)

- Any **1.000 weak-200** Virgin number is **circular**: weak labels ARE the keyword rules (`src/virgin_intents.py:KEYWORDS`), so simple scores 1.000/1.000 by construction and final's train-subset acc 0.949 is equally circular. Never cite weak-200 accuracy. True ceiling is weak-vs-human agreement (Virgin 0.795, κ 0.772 on 200; Apple 0.517, κ 0.465 on 60) — Virgin's higher overlap is why simple beats final on intent here too.
- Virgin **human-200 is single-annotator AI-assisted** (60 manual-style + 140 rulebook-assisted, 41 flips; no inter-annotator κ yet). n=200 → CIs ≈±0.07 on acc; per-intent F1 on ~14–29/stratum unstable (±~20% — e.g. accessibility 0.848→0.421). Citing Apple human numbers as Virgin results would be a transfer fallacy — Apple rows above are reference only.
- Groundedness 0.935 ≥4 (mean 4.21) rewards templates by design (≤280 chars, acknowledge→step→DM, no invented £/HH:MM), not human factuality — heuristic would score 4–5 even on F4a/F7 (right words, wrong decision). Safety recall 1.000 on **n=3** has CI ~0.4–1.0 (gate NOT claimable); money recall 0.800 on n=20 is the better-powered escalation signal (up from 0.350 pre-fix — the gate fix is real, not a metric trick).
- Latency (virgin index p50 7.1ms, Apple end-to-end p50 180ms) is dev-CPU, not prod; burst-month slice (post-2017-11-15) + thin pre-2017 tail shift results; 5/9 failure-PROBE pass rate flatters (F1/F2 pass on draft safety while riding keyword rails; F3a passes via over-escalation accident).
- Trust esc-vs-human κ 0.347 + money/safety slices + failure FAILs + flips, not a single accuracy. Full 200-human double-label + adjudication needed for ship.
